 47 |
 48 | ||| Acquires the mutex identified by `mutex`. The thread blocks until the mutex
 49 | ||| has been acquired.
 50 | |||
 51 | ||| Mutexes are recursive in Posix threads terminology, which means that the
 52 | ||| calling thread can use mutex-acquire to (re)acquire a mutex it already has.
 53 | ||| In this case, an equal number of mutex-release calls is necessary to release
 54 | ||| the mutex.
 55 | export
 56 | mutexAcquire : HasIO io => Mutex -> io ()
 57 | mutexAcquire m = primIO (prim__mutexAcquire m)
 58 |
 59 | ||| Releases the mutex identified by `mutex`. Unpredictable behavior results if
 60 | ||| the mutex is not owned by the calling thread.
 61 | export
 62 | mutexRelease : HasIO io => Mutex -> io ()
 63 | mutexRelease m = primIO (prim__mutexRelease m)

 97 | ||| Waits up to the specified timeout for the condition identified by the
 98 | ||| condition variable `cond`. The calling thread must have acquired the mutex
 99 | ||| identified by `mutex` at the time `conditionWait` is called. The mutex is
100 | ||| released as a side effect of the call to `conditionWait`. When a thread is
101 | ||| later released from the condition variable by one of the procedures
102 | ||| described below, the mutex is reacquired and `conditionWait` returns.
103 | export
